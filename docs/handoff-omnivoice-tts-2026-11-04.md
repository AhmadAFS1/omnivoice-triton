**The useful configuration discovery.** The small hybrid cache retained 8 graphs with a 16,384 row-token budget. The B1 fixture cycles through 64 exact tensor shapes. On the 5090 that caused 279 captures and 271 evictions across warmup plus timed work. With **64 graph slots and 65,536 row tokens**, all 64 fit and the B1 timed portion had no recaptures/evictions. C1 throughput improved **2.266 → 5.488/sec**, p95 **450 → 197ms**, GPU busy time **39.8% → 88.1%**, and mean framebuffer use **3,248 → 6,535MiB**. The larger cache also helped the older-CPU 5070 Ti substantially. One wide-cache 5090 worker reached 5.68/sec at C8 versus about 4.53/sec for two ordinary eager workers.

This used existing branch options, not a new kernel implementation. The corresponding candidate launch settings are `--runner hybrid --max-cuda-graphs 64 --max-cuda-graph-row-tokens 65536 --max-batch-requests 1 --batch-collect-ms 0 --audio-decode-batch-size 1 --disable-unused-kv-cache --response-cache-max-bytes 0 --no-asr`. The scheduled-load assay additionally used `--max-pending-requests 4`. Pass `num_step=16`, `speed=1`, `denoise=true`, `postprocess_mode=off`, `insert_pauses=false` in requests. API omitted-step fallback remains 32. The row-token memory policy is a heuristic plus runtime headroom checks, not a hard VRAM partition. New utterance/reference lengths can introduce unseen shapes and capture overhead; the 64-shape warmed result is not universal.

**Hardware-level interpretation.** The 5070's matched eager C1 is about 6.8% faster than the 4070. NVIDIA's same-precision comparison gives roughly 6% more dense FP16/BF16 Tensor throughput with FP32 accumulation, but 33% more memory bandwidth and a larger L2 cache. FP4 sparse AI TOPS are not the FP16 arithmetic measured here. Current traces show many CUTLASS/attention implementations labeled sm80; implementation-template names do not mean the physical GPU was misidentified. The 5090's roughly 17,199 B1 kernels and the measured graph-cache improvement expose substantial CPU/capture/launch overhead. Once removed, the iterative backbone's GEMMs and attention dominate; WAV encoding and codec decode are smaller for these short turns. Synthetic device-copy GB/s is not measured model DRAM utilization, and `nvidia-smi` busy percent is not theoretical FLOP utilization. Consumer Blackwell sm120 differs from data-center Blackwell sm100.
