# Raw 5,000-request assay — CPU-ready, GPU execution pending

CPU protocol tests ran on **Apple M5 Pro, Python3.14.7, 4 November2026** with a local synthetic HTTP/WAV responder. They execute no TTS, CUDA, ASR, or paid API. The planned inference host is **NVIDIA GeForce RTX4070Ti**, UUID `GPU-5aada52f-9af2-4506-47f7-75e99aaf51ee`. Historical host evidence reports physical12282MiB / Torch-visible12481134592bytes, driver610.57.04, CUDA12.8. Those hardware values are reused context; execution records fresh GPU/VRAM, packages and idle evidence before launch. No ASR may share its GPU during the timed assay.

The workload is **5,000 fresh inference requests cycling the original1,000 published text/language/reference inputs five times**. It is not5,000 novel inputs. Ten input-disjoint warmups and all nine original reference registrations occur before the cohort. Frozen V4 `load_inputs`, `effective_signature`, `build_command`, `validate_runtime`, runtime/seed/hardware helpers and deferred SoundFile retention are reused unchanged. Input/source/helper/reference SHAs are checked in the default dry plan. Execution additionally streams SHA verification of all13 pinned model assets, rather than loading gigabyte weights into client RAM.

The fixed source is ce48b253e66b951d87ea42919f945828c62e96a4; Triton eager FP16, maximum batch1, KVoff, sixteen full steps, speed1, complete original references, postoff, serial codec1, generated-response cache0, graphs0. Root explicitly selected `--batch-collect-ms0` for this run: this differs from the previous measured B1 setting5ms and an earlier frozen job-plan value10ms. It is an operator-setting difference, not a new neural algorithm. Maximum pending generation requests is6,000; client and server inherit RLIMIT_NOFILE at least16,384. `server-process-limits.txt` checks the actual server inheritance.

`raw_burst_v1.py` opens all5,000 distinct TCP sockets with at most256 simultaneous connection attempts. Each socket completes a `/healthz` request before reuse. File descriptors and local endpoints must both be unique; the socket must remain live before the barrier. Any failure prevents the entire cohort from starting: there is no silent reduction, replacement connection, or retry. The timed cohort uses direct `asyncio` streams, one preconnected TCP socket per POST, without a shared HTTPX connection pool. The HTTPX control client only handles setup, final health, and a declared five-second health monitor.

Prebuilt request bytes are sent from a common event barrier. Every actual `writer.write` call and completed drain records its offset from that barrier; this is user-space POST dispatch evidence, not a NIC timestamp. Full-body completion uses strictly validated HTTP/1.x status/headers and Content-Length. Duplicate headers, missing/invalid length, transfer encoding/chunked, compression, oversized headers/bodies, truncated bodies and connection errors remain distinct retained outcomes. Valid responses with `Connection:close` are fully read. No first-byte/streaming result is called completed audio. Original partial bytes, HTTP error bodies and protocol metadata are saved after the cohort.

All complete response bodies are held without hashing, decoding or disk I/O during the cohort. Aggregate retained/in-flight body reservations are capped at1GiB; the per-response cap is2MiB. Prior original1,000 B1 bodies totaled180,107,360bytes, so five identical-length cycles would total900,536,800bytes; this is an estimate, not an assumption about the new run. Python objects, StreamReaders and kernel socket buffers have additional overhead: actual client peak RSS at network completion is recorded separately from payload reservations. A RAM-cap failure is recorded rather than dropping bytes and counting success. Every complete HTTP200 WAV is SHA-checked, decoded and saved after timing through the unchanged V4 helper. Standard `quality-manifest.json`, ASR-ready/unmapped/invalid lists, request rows, original corpus/proxy/reference metadata and all errors are retained. Signal-valid audio is not word/voice certification.

`raw_burst_server_v1.py` changes only this benchmark process: Uvicorn keepalive600seconds, resolved parser/event-loop evidence, and labeled CPU batch counters. Its `_execute_batch` observer preserves original arguments/results/exceptions and counts started logical batch members and successful completed batch-future members. These are not HTTP or word-quality successes. The API seed applies before API import; observers are installed after that import and before lifespan. Frozen product files/defaults remain unchanged.

The ce API has no cumulative batch execution counter and does not report per-request `Inference-Executed`. Its absent header is retained as **unreported**, never true. Neural work is instead checked by the benchmark counter difference after warmups, disabled-cache health, and independent `Executing batch`/`Completed batch` member totals from the exact cohort segment of the retained server log. A full pass requires5,000 completed bodies, basic signal validity,5,000 successful B1 batch-member increments,5,000 independent log members and cache-disabled health. HTTP429/500, missing/partial bodies, invalid audio, transport errors, timeout and CUDA failures remain in the5,000-offer denominator. Summaries also report conditional successful-body latency and whole-cohort completion separately.

The outer supervisor requires a fresh exact-controller/wrapper/config SHA root lease naming this GPU/source and all5,000 requests. Its total bound is2,400seconds; the inner cohort is2,200seconds. It owns a fresh process group, and the server explicitly inherits that same group, so timeout/interrupt cleanup stops both even if the client exits unexpectedly. CUDA faults stop the cohort and use process teardown; no retry or neural fallback occurs. Fresh independent SMI idle evidence is required in `RAW_BURST5000_COMPLETE_IDLE.json`. Output directories use `exist_ok=False`; neither previous Split experiments nor V4 source/results are overwritten.
